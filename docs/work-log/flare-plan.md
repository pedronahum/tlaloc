## Results

| Item | Status | Result |
|---|---|---|
| Delta-rule state committed once per step | done | A speculative export's GATED_DELTA_RULE takes `commit = "records"` (verify) or `"final"` (prefill) with a `STATE_COMMIT` input `[B, 3]` (base, target, count) and a records pool per layer: a verify step applies the previous step's accepted records to the base state, writes that starting state at the target and keeps one record per token (key, `beta (v - kᵀS)`, log decay); no state per token. The state after any accepted count equals the per-token write bit for bit (`triton/kernels/bench/gated_delta_bench.cu`); the kernel and the XLA forms equal the interpreter in both modes, f32 and bf16 pools (`PjrtFusedGatedDeltaTest`); the interpreted and device MTP tests give transformers' ids and the oracle's drafts, chained steps included. Kernel, 4 sequences × 4 tokens: 0.200 → 0.062 ms per layer. Server compute per verify step (`profile.sh decode:256:48`): 4 streams 50.17 → 45.77 ms, 1 stream 27.56 → 26.92 ms. Categories: 1 stream 145.8 → 150.5 tokens/s per reply; 4 streams aggregate 161.7 → 169.4 tokens/s, per reply 83.0 → 83.7, TTFT 0.20 / 0.21 s. A generation's last step that keeps fewer tokens than it accepted sets the count to those (the backend's, not the step's). |
| Checkpoints at a prompt's end and at named lengths | done | With the prefix cache a prompt is also kept at its end and at the lengths of the request parameter `checkpoints` (a call ends there); a prefix ending inside a page keeps a copy of that page and a sequence starting from it copies it again. `openai_server.py` names the end of a new chat's leading system messages. Eviction takes prefixes no other cached prefix extends first. `speculative_checks.py`: a prompt extending an earlier one of 41 tokens, and one sharing a checkpoint of 23, start from those prefixes and give the ids of a server without the cache (`a prompt started from a cached prefix ending inside a page`). |
| Poisoned pools | done | `TLALOC_POISON=1`: before each step with none in flight, the state slots no step may read are set to NaN and free KV pages to 0x47 bytes (5.1e4: attention reads positions past a sequence's length in its last page with weight 0, so a NaN there spoils the sum and a large finite value does not; the f16 prefill form overflows 8e37). The unchained Qwen3.5 fixture server runs with it and gives transformers' ids (`verify.sh` step 9). It found no stale read. |
| Per-call timeline | done | `TLALOC_TIMELINE=1` logs each call's times and its rows' arrivals. At 4 streams the harness's four prompts arrive together; each prompt's prefill call starts 2.1 ms after its arrival (median), no decode call runs in between, and the call prefills the four together: 139 to 243 ms by entry (packed 256 rows 182.5 ms, padded 4 × 64 139.2 ms), against 107 ms for one prompt. The earlier reading of the 4-stream TTFT (two decode steps ahead of the prefill) was wrong; it is that call. |
| Bound from measured drift (AdamW) | done | `PjrtDeviceAdamWTest` bounds each step's loss by twice the drift of the host loop when every gradient element is perturbed by up to 2^-11 (TF32's unit roundoff), at least 0.5 %, instead of a fixed 0.5 %. |
