## What this changes

After the passes that followed this re-audit, **ten of the thirteen findings are closed** (SV-1,
SV-2, SV-3 for KV-only models, SV-4, SV-7, SV-8, SV-9, SV-11, SV-13, and SV-12's `/health` and
parameters), SV-10 is resolved by correcting a false claim and naming the limitation it hid, and
two are partly closed (SV-5, bounded by measurement; SV-6, whose tokenize-before-check ordering
was not re-verified). Every closure has a test that was seen failing with the fix disabled.

**What is deliberately not closed, and why.** Three boundaries are named rather than papered over:

1. **One shared API key is one trust domain.** Owner-scoped reuse isolates cooperating callers;
   a caller sharing the key can still claim another's `user`. The stronger fix is a per-key
   identity, which is a configuration and auth change, not a bug fix.
2. **The Python endpoint's own `Sequences` is unchanged**, so SV-9's oracle is still open there.
   It also still carries the `Detokenizer.add` quadratic and the ignored `stop` (SV-12's tail).
3. **An abandoned `stream:false` request runs to `max_tokens`** (SV-10). `HttpExchange` has no
   liveness probe; cancelling earlier means committing to a chunked body before the answer
   exists.

These are the next pieces of work, in that order of value.
